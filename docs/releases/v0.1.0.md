## EnzyDock 0.1.0

First public release.

**Protein + substrate → binding affinity + 3D poses**, on Windows and macOS,
with no command line involved. Paste a SMILES string, drop in a `.pdb`, press
**START DOCKING**, and get the affinity, the pose files, a report and an
interactive 3D view of the binding site.

**AutoDock Vina 1.2.7 ships inside the application** — nothing else to
install, no Python, no separate engine download.

### Windows — running the app

1. **Download and verify.** The digest is in the `.sha256` asset:

   ```bat
   certutil -hashfile EnzyDock-0.1.0-win64.zip SHA256
   ```

   Expected:
   `4476442662e5e7b401e06fb4b0b238f7d723bbc5a7bbdac0fc7237b6beae4425`

   On macOS or Linux the sidecar is directly usable:

   ```sh
   sha256sum -c EnzyDock-0.1.0-win64.zip.sha256      # Linux
   shasum -a 256 -c EnzyDock-0.1.0-win64.zip.sha256  # macOS
   ```

   Both print `EnzyDock-0.1.0-win64.zip: OK`.

2. **Extract to a short path** — `C:\EnzyDock`, not the WeChat received-files
   folder. Deep paths break the embedded 3D viewer.

3. **Run `EnzyDock\EnzyDock.exe`.**

4. **If Windows Defender quarantines something:** that is a false positive on
   a statically linked binary. Run `EnzyDock\check-install.bat` to confirm the
   download is complete, then allow the file. The application never needs
   AutoDock Vina installed separately.

`EnzyDock\HOW-TO-RUN.txt` (Chinese) and `EnzyDock\BUNDLE-MANIFEST.txt` ship
inside the archive.

### macOS — building the app

PyInstaller cannot cross-compile, so the `.app` is produced on the machine
that will run it. That is the only reason this release ships a build kit
instead of an application.

1. **Unzip the kit** anywhere — a path without non-ASCII characters is safest.

2. **Double-click `双击我构建 EnzyDock.command`.** It creates a virtual
   environment, installs the dependencies, runs the test suite, builds
   `EnzyDock.app` and verifies the bundle end to end. 15–25 minutes, and a
   network connection for the first run (300–600 MB of dependencies).

3. **Drag `EnzyDock.app` into `/Applications`.**

If macOS blocks the script the first time, right-click → **Open** → **Open**
again. That prompt is expected for anything downloaded from the internet, and
it only has to be confirmed once.

`先看我-READ-ME-FIRST.txt` (Chinese) is inside the kit and covers the common
failure modes.

### What was verified for this release

- **545 automated tests** (543 passing, 2 skipped), including 7 end-to-end
  tests that run the real docking engine against a real protein.
- **27 bundle checks** against the packaged Windows application
  (`scripts/verify_bundle.py`), including a live docking run *inside the
  bundle* and a real 3D view with a working WebGL context.
- The Windows bundle was rebuilt from a clean PyInstaller workpath and
  re-verified, so the shipped archive matches the current source.
- The macOS packaging chain (pack → split → verify → merge) is exercised
  end to end in the test suite against a synthetic `.app`, so the Mac half of
  the release process is covered even though the real `.app` can only be
  built on a Mac.

### Requirements

- Windows 10 / 11, 64-bit
- macOS 12 or newer, Apple Silicon or Intel
- ~1 GB of free disk space

### Known limitations

- The macOS application cannot be shipped pre-built from a Windows machine,
  so this release ships the build kit instead.
- The bundled engine is the official CPU-only build of AutoDock Vina 1.2.7,
  redistributed unmodified under the Apache License 2.0.
- Interaction analysis is a geometric screen (H-bonds, salt bridges, halogen
  bonds, π-stacking, hydrophobic contacts) — not a full rescoring calculation.
