EnzyDock 使用说明（macOS 免安装版）
================================================================

一、这是什么

    这是 EnzyDock 的 macOS 免安装版本，程序自带 Python 和全部科学计算依赖。
    电脑上不需要安装 Python、RDKit、PySide6、Homebrew 或 Xcode，双击就能用。

    支持 Apple Silicon（M1/M2/M3/M4）与 Intel 两种 Mac。


二、怎么用

    0. 如果收到的是几个 .001 / .002 / .003 分卷，先把它们和
       merge-parts.command 放在同一个空文件夹里。

       ★ zip 不会保存「可执行」属性，所以解压后要先补一次权限。
         打开「终端」，输入 chmod +x 和一个空格，把 merge-parts.command
         拖进终端窗口（会自动填上它的路径），回车：

             chmod +x merge-parts.command

         （不做这一步的话，双击会用它打开文本编辑器而不是运行它。）

       然后双击 merge-parts.command（首次可能仍需右键 → 打开）。
       它会自动拼回完整的 zip 并核对指纹，
       看到 [ OK ] the archive is complete 就继续第 1 步。

       不想用脚本也可以在「终端」里直接拼：

           cat 分卷文件名.001 分卷文件名.002 ... > 完整.zip

    1. 双击收到的 zip 解压（macOS 自带「归档实用工具」就行），
       解压后应该得到：
           EnzyDock.app          ← 应用程序本体
           check-install.sh      ← 完整性自检脚本
           HOW-TO-RUN-mac.txt    ← 本文件

    2. 把 EnzyDock.app 拖进「应用程序」（/Applications）文件夹。
       ★ 不要在「下载」或微信接收目录里直接运行 —— 那里随时会被清理，
         .app 一旦被移动或部分删除就再也起不来了。

    3. 第一次启动：在「应用程序」里右键点 EnzyDock.app →「打开」，
       再点一次「打开」确认。
       这是因为 macOS 会拦截一切从网上下载的程序。只需确认一次，
       以后直接双击即可。

       如果系统仍然拒绝，或者提示"已损坏"、"无法验证开发者"，
       打开「终端」，粘贴执行（注意引号里的路径按实际位置改）：

           xattr -dr com.apple.quarantine /Applications/EnzyDock.app

       然后再双击打开。

    4. 首次启动约 5~15 秒，出现主窗口即成功。

    5. 跑完一次对接后，右下角的 Result 面板有两个页签：
           Poses         打分表（点一行就在 3D 里换一个构象）
           Interactions  该构象与蛋白的接触（氢键 / 盐桥 / 卤键 /
                         π 堆积 / 疏水接触），列出受体残基、配体原子和距离
       3D 视图上方还有一排开关，勾上 Contacts 就会在结构里画出这些接触
       （虚线颜色对应左下角的图例）；勾上 Surface 会显示蛋白表面。


三、启动时提示"无法打开，因为 Apple 无法检查其是否包含恶意软件"

    这是 Gatekeeper 的例行拦截，不是程序有问题。三种解决方法，
    任选一种：

    1. 右键 EnzyDock.app →「打开」→ 在弹窗里再点「打开」。
       （直接双击会被拦，右键打开可以绕过首次检查。）

    2. 「系统设置」→「隐私与安全性」，往下滚到"安全性"一栏，
       会看到"已阻止使用 EnzyDock"，点旁边的「仍要打开」。

    3. 终端里执行：

           xattr -dr com.apple.quarantine /Applications/EnzyDock.app

    如果提示的是"EnzyDock.app 已损坏，无法打开"，同样用第 3 种方法，
    绝大多数情况是下载不完整或被解压工具破坏了权限位。


四、只收到了一个 13 MB 的可执行文件？那一定启动不了

    在 macOS 上「程序本体」是 EnzyDock.app 这个文件夹（在访达里显示为
    一个图标），它要用的 Python、RDKit、Qt 和 3D 组件全在里面
    （约 600 MB、500 多个文件）。

    千万不要只拷贝 EnzyDock.app 里面的某一个文件，也不要把 .app 里的
    内容拖出来单独发 —— 会报 "Failed to load Python DLL" 之类的错。

    最简单可靠的做法：发打包好的 zip（一个文件，解压出来就是完整的
    应用程序），或者按上面的分卷方式发。


五、检查这一份是不是传全了

    在存放 EnzyDock.app 的文件夹里，双击 check-install.sh
    （首次可能需要右键 → 打开，或先在终端执行
      chmod +x check-install.sh 再双击）。

    它会核对关键文件和文件总数，并真的启动一次内置的对接引擎。
    全部显示 [ OK ] 且最后是 "This copy looks complete." 就没问题；
    有 [FAIL] 就说明传输不完整，让对方重新发一次。

    想手工核对 zip 的指纹（打包时会把 SHA256 一起发给你）：

        shasum -a 256 EnzyDock-0.1.0-macos-arm64.zip

    两边一致就说明传输无损，问题出在解压环节。


六、AutoDock Vina 已内置，无需另行安装

    这一版把对接引擎（AutoDock Vina 1.2.7）随程序一起提供，位置在：

        EnzyDock.app/Contents/Resources/app/resources/bin/vina_mac_aarch64

    （Intel Mac 上对应的是 vina_mac_x86_64。）

    解压后直接就能对接，不需要 brew install，也不需要下载任何东西。
    （AutoDock Vina 采用 Apache 2.0 许可，允许随软件一起分发；
      版权归 The Scripps Research Institute，许可证正文在
      Contents/Resources/app/resources/licenses/ 目录下。）

    ★ 如果软件提示 "The AutoDock Vina that ships with EnzyDock could not
      be started"，按顺序检查：

      1) 是不是 .app 被移动或部分删除了 —— 重新解压一次；
      2) 引擎丢了可执行权限 —— 终端执行：
             chmod +x "EnzyDock.app/Contents/Resources/app/resources/bin/vina_mac_aarch64"
      3) 被 Gatekeeper 隔离 —— 终端执行：
             xattr -dr com.apple.quarantine /Applications/EnzyDock.app

    ★ 想换成自己的引擎（QVina2、Smina 或更新版本的 Vina）也可以：
      打开菜单 File → Set Docking Engine ...，选中你的文件即可，
      它会优先于内置版本；再用 File → Use the Bundled Docking Engine
      可以切回内置的那一份。


七、3D 视图是空白的？

    远程桌面、虚拟机或某些受限环境下拿不到图形加速，请用兼容模式启动。
    在「终端」里执行：

        /Applications/EnzyDock.app/Contents/MacOS/EnzyDock --web-compat

    兼容模式会让 QtWebEngine 用软件渲染画 WebGL，牺牲一点速度换取能出图。
    也可以做一个"替身"（Automator 应用或 .command 脚本）把这一行存起来
    方便双击。


八、想知道环境是否正常

    在「终端」里执行：

        /Applications/EnzyDock.app/Contents/MacOS/EnzyDock --selftest \
            --report ~/Desktop/enzydock-selftest.txt

    （路径里有空格时，整个路径要用引号包起来。）

    它会把每一项后端检查（RDKit、转换器、Vina 等）的结果写进那个 txt，
    把 txt 发回来即可定位问题。软件内的 Help 菜单里也有 Run Diagnostics。

    想连对接一起体检（会真跑一次对接，约 10~30 秒）：

        /Applications/EnzyDock.app/Contents/MacOS/EnzyDock --selftest \
            --selftest-pdb ~/某个.pdb --selftest-dock \
            --report ~/Desktop/enzydock-selftest.txt

    这份报告会多出两项：一次真实的 AutoDock Vina 对接，以及
    "Interaction analysis"（用刚才那个构象做 3D 相互作用分析）。
    两项都是 PASS，说明 3D 结果视图（蛋白 + 接触）在本机可用。


九、常见问题

    Q: 提示"未打开，因为它来自身份不明的开发者"
    A: 见第三节，右键打开 / 隐私与安全性 / xattr 三条路任选。

    Q: 双击 check-install.sh 打开了文本编辑器
    A: 它还没有可执行权限。终端里 cd 到该目录，执行
           chmod +x check-install.sh
       再双击即可。

    Q: 提示"EnzyDock.app 已被移到废纸篓"
    A: 系统把某个文件当成残留了。到「废纸篓」里把它放回原处，
       或重新解压一份 zip，然后按第三节解除隔离。

    Q: 工作目录在哪？
    A: 打包版的工作目录是 ~/Documents/EnzyDock（每次对接会新建一个带
       时间戳的子文件夹）。设置与日志在
       ~/Library/Application Support/EnzyDock。
